# VPN Proxy Wrapper

Простая утилита для запуска любых команд через HTTP прокси, VLESS или Outline в Linux.

## Описание

`vpn` - это bash-скрипт, который позволяет запускать любые команды через HTTP/HTTPS прокси, VLESS или Outline/Shadowsocks протокол. Прокси настраивается один раз в файле `~/.vpn_proxy`, после чего вы можете запускать любую программу через прокси просто добавив префикс `vpn` перед командой.

Если у вас подписка со списком серверов, `vpn` умеет читать её и переключать страну:

```bash
vpn use de                   # выбрать Германию
vpn curl ifconfig.me         # запрос через Германию
vpn -c jp npm install        # разово через Японию
```

## Возможности

- Работает с любыми программами, поддерживающими переменные окружения HTTP_PROXY/HTTPS_PROXY
- Поддержка HTTP прокси с авторизацией (логин/пароль)
- Поддержка VLESS протокола (через xray-core)
- Поддержка подписок со списком серверов и выбором страны
- Подписки в формате v2ray-JSON (массив Xray-конфигов), помимо base64/plain text
- Ссылки `incy://` — через официальный клиент INCY в изолированной коробке
- Автоматический запуск xray для VLESS подключений
- Поддержка Outline/Shadowsocks (ss://) с Outline-префиксом (через outline-sdk)
- Автоматический запуск локального outline-proxy для ss:// подключений
- Простое обновление прокси через текстовый файл
- Не требует настройки каждой программы отдельно
- Легкая установка и удаление

## Установка

### Автоматическая установка

```bash
sudo ./install.sh
```

Скрипт автоматически:
1. Установит `vpn` в `/usr/local/bin/`
2. Создаст файл конфигурации `~/.vpn_proxy` из примера
3. Установит правильные права доступа

### Ручная установка

```bash
# Копируем скрипт
sudo cp vpn /usr/local/bin/vpn
sudo chmod +x /usr/local/bin/vpn

# Создаем файл с прокси
cp vpn_proxy.example ~/.vpn_proxy
chmod 600 ~/.vpn_proxy

# Редактируем прокси данные
nano ~/.vpn_proxy
```

## Настройка

Отредактируйте файл `~/.vpn_proxy` и укажите данные вашего прокси в одном из поддерживаемых форматов:

### HTTP Proxy

```
IP:PORT:USER:PASS
```

**Примеры:**

```
# С авторизацией
168.80.200.220:8000:username:password

# Без авторизации
192.168.1.1:3128::
```

**Важно:** Формат строгий - четыре поля разделенные двоеточием. Если логин/пароль не нужны, оставьте их пустыми, но двоеточия должны быть.

### VLESS Protocol

Для использования VLESS протокола необходимо установить [xray-core](https://github.com/XTLS/Xray-core).

**Быстрая установка xray:**
```bash
bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install
```

**Формат VLESS URL:**
```
vless://UUID@HOST:PORT?параметры#имя
```

**Пример:**
```
vless://12345678-1234-1234-1234-123456789abc@example.com:443?flow=xtls-rprx-vision&security=reality&type=tcp&alpn=h2,http/1.1&sni=example.com&fp=chrome&pbk=YOUR_PUBLIC_KEY_HERE#example
```

При использовании VLESS, скрипт автоматически:
1. Парсит VLESS URL
2. Генерирует конфигурацию для xray
3. Запускает xray в фоновом режиме (если еще не запущен)
4. Использует локальный HTTP прокси от xray

Поддерживаемые транспорты: `tcp`, `ws`, `xhttp` (`splithttp`), `httpupgrade`, `grpc`.
Поддерживаемые режимы безопасности: `reality`, `tls`, без шифрования.

### Подписка (выбор страны)

Если провайдер даёт ссылку на подписку — укажите её вместо отдельного сервера:

```
https://cdn.example.com/sub/vless/12345678-1234-1234-1234-123456789abc
```

Подписка — это URL, отдающий список `vless://` ссылок (обычно в base64), по одной
на страну. Скрипт скачивает список, кэширует его на сутки и даёт выбирать страну.

```bash
# Показать доступные страны (текущая помечена звёздочкой)
vpn list

#   ae     emirates       🇦🇪 ОАЭ (AE)
#   ge     germany        🇩🇪 Германия (GE)
#   jp     japan          🇯🇵 Япония (JP)
# * nl     netherlands    🇳🇱 Нидерланды (NL)

# Выбрать страну по умолчанию
vpn use de

# Запустить команду через выбранную страну
vpn curl ifconfig.me

# Разово через другую страну, не меняя выбранную
vpn -c jp curl ifconfig.me

# Обновить список серверов принудительно
vpn update

# Какие подключения сейчас подняты
vpn status

# Остановить одно или все
vpn stop jp
vpn stop all
```

**Как искать страну.** Подойдёт код (`de`), имя хоста (`germany`), их сокращение
(`neth`) или кусок названия в нижнем регистре (`соц`). Привычные коды работают,
даже если провайдер пометил сервер иначе: в подписке YouFast Германия помечена
как `(GE)`, но `vpn use de` её всё равно находит.

**Параллельные страны.** Для каждой страны поднимается свой процесс xray на своей
паре портов, поэтому `vpn -c de ...` в одном терминале и `vpn -c jp ...` в другом
не мешают друг другу. Процессы запускаются лениво и переиспользуются.

#### Подписки в формате v2ray-JSON

Не всякая панель отдаёт список ссылок. Некоторые (в их числе Remnawave) присылают
массив целых Xray-конфигов — по одному на сервер, у каждого свои `inbounds`,
`routing` и имя в `remarks`. Такое тело опознаётся по структуре и сворачивается
в одну `vless://` ссылку на сервер, дальше всё идёт обычным путём.

Берётся только исходящий proxy-outbound: `vpn` сам выбирает страну и поднимает
свои inbound'ы, так что чужой роутинг в лучшем случае лишний, а в худшем перебил бы
выбор страны. Побочный эффект — пункты, которые на деле являются профилями
роутинга, а не локациями (`🧲 Торренты`, `📶 Белые списки`), выглядят обычными
серверами и отличаются только хостом. Записи на протоколах, которые `vpn` не тянет
(hysteria, trojan), отбрасываются, а не превращаются в ссылки, падающие позже
на `xray -test`.

Этот формат разбирает `v2ray_json.py` — нужен `python3` (только stdlib). Без него
JSON-подписки не поддерживаются, остальные форматы работают как прежде.

#### Ссылки incy:// — через официальный клиент INCY

Некоторые провайдеры выдают подписку не голым URL, а deep-link'ом
`incy://crypt1/…` и банят подписку, если её забирает не их клиент: INCY ходит за
подпиской со своими заголовками (`x-client: INCY`, `x-hwid`, `x-device-os`, ...).
Поэтому `vpn` такие ссылки **не расшифровывает**. Вместо этого он поднимает
настоящий INCY в изолированной «коробке» и пускает команды через его локальный
порт. Ссылку кладёте в `~/.vpn_proxy` как есть:

```
incy://crypt1/AAECAwQFBgcICQoLNyIQL3rDwRZqnyoD8pGK…
```

```bash
vpn incy setup               # первый раз: скачать INCY, импортировать ссылку
vpn curl ifconfig.me         # дальше — как обычно
vpn list                     # серверы из подписки (* — текущий)
vpn use 3                    # выбрать сервер: номер, имя или кусок имени
vpn update                   # INCY перечитает подписку
vpn incy ui                  # показать окно INCY (Linux — по VNC)
vpn incy hwid                # показать HWID этой коробки
vpn incy log                 # логи коробки и INCY
vpn stop incy                # остановить
```

Что происходит под капотом:

- INCY (portable-сборка под Linux, `.dmg` под macOS) ставится в
  `~/.local/share/vpn/incy/app`, sha256 сверяется с закреплённым для версии.
  Без доступа к GitHub: `VPN_INCY_ASSET=/путь/к/incy-linux-x64-portable.zip`.
- Ссылка передаётся INCY при запуске, он сам забирает подписку. Сменилась ссылка
  в `~/.vpn_proxy` — база INCY пересоздаётся.
- INCY работает в режиме PROXY_ONLY: ни TUN, ни системного прокси, только
  локальный порт на `127.0.0.1`. Для обычных подписок это mixed-порт (HTTP +
  SOCKS5) с паролем, который INCY генерирует сам, и `vpn` выставляет
  `http_proxy=http://user:pass@127.0.0.1:ПОРТ`. Если же подписка отдаёт «полный»
  Xray-конфиг провайдера (LEDOKOL, часть Remnawave-панелей), порт и формат
  входа задаёт провайдер — обычно это SOCKS; тогда `vpn` выставляет
  `all_proxy=socks5h://127.0.0.1:ПОРТ`. И то, и другое прозрачно работает с
  `vpn curl/git/...`.
- Порт по умолчанию — **10808**: именно его INCY 3.8.8 проверяет на готовность, и
  на него же прошиты «полные» конфиги провайдеров, так что всё совпадает без
  ухищрений. Если 10808 уже занят другим прокси-клиентом — задай
  `VPN_INCY_PORT=<свободный>` (но учти: провайдерский full-config, прошитый на
  10808, на другом порту не поедет — тогда порт 10808 придётся освободить).
- HWID, который видит провайдер, по умолчанию тот же, что у INCY, установленного
  обычным способом на этой машине: он считается из machine-id, hostname и имени
  пользователя, их коробка не подменяет. Лишний слот устройства не тратится.

#### Один HWID на несколько своих установок

Виртуалка на вашем маке по умолчанию считается у провайдера отдельным
устройством: у неё свои machine-id и hostname, поэтому и HWID другой. Если это
по сути тот же компьютер (VM на вашем же маке) и вы хотите, чтобы они заняли
один слот устройства, HWID можно зафиксировать.

INCY хранит итоговый HWID в текстовом файле и при старте использует его как
есть, если это валидный UUID. Коробка даёт на это две ручки:

```bash
# на маке — посмотреть HWID, который использует ваш обычный INCY:
cat "$HOME/Library/Application Support/incy/hwid"
#   (если на маке тоже коробка, а не обычный INCY: vpn incy hwid)

# на виртуалке — закрепить тот же HWID:
vpn incy hwid 1A2B3C4D-5E6F-7A8B-9C0D-1E2F3A4B5C6D
```

Значение переживает перезапуски и смену серверов (INCY не трогает валидный
файл). Для скриптовой установки есть переменная `VPN_INCY_HWID=<UUID>` — тогда
коробка прописывает HWID при каждом запуске. Формат — канонический UUID
8-4-4-4-12; другое коробка отклонит, чтобы в заголовок не ушёл мусор.

Это ваши собственные устройства и ваш лимит — так вы не плодите лишние слоты.
Передавать свой HWID чужим людям смысла не имеет: провайдер считает устройства
именно по нему.

Изоляция:

- INCY видит подменённый домашний каталог (`-Duser.home`): его настройки,
  база и логи лежат в `~/.local/share/vpn/incy/home` и не пересекаются с
  обычным INCY, если он у вас тоже стоит.
- `networksetup`, `osascript`, `gsettings`, `kwriteconfig*`, `xdg-mime` и т.п.
  подменены заглушками (вызовы пишутся в `~/.cache/vpn/incy-box/shim.log`).
  Это важно: при выходе INCY безусловно выключает системный прокси на всех
  интерфейсах (на macOS — с запросом пароля админа, если не вышло), а при
  запуске регистрирует себя обработчиком `incy://`. Обычному VPN-клиенту,
  работающему рядом, это бы всё ломало.
- Linux: окно рисуется в Xvfb, сам INCY запускается в bubblewrap — система
  только для чтения, домашний каталог пользователя не виден, писать можно
  только в каталог коробки. Если bubblewrap нет или user namespaces закрыты,
  INCY запускается без песочницы (`VPN_INCY_SANDBOX=on` — тогда ошибка,
  `off` — не пытаться).
- macOS: обычный запуск свёрнутым, без иконки в доке; песочницы нет
  (`sandbox-exec` устарел и с JVM работает плохо).

Зависимости: python3; на Linux ещё `xvfb`, `bubblewrap`, `unzip`, для `vpn incy
ui` — `x11vnc`. На macOS ничего ставить не нужно. Клиент — JVM-приложение,
в фоне занимает около 300 МБ памяти (на Linux плюс ~60 МБ Xvfb).

Ограничения:

- Сервер в INCY один на всё, поэтому `-c` в этом режиме не работает —
  переключайтесь через `vpn use`.
- INCY 3.8.8 проверяет готовность xray подключением к порту 10808, даже если
  в настройках порт другой, и через 20 с без ответа отключается. Поэтому порт по
  умолчанию = 10808 (INCY сам себе отвечает на проверку). Если ты задал другой
  `VPN_INCY_PORT`, коробка на время подключения держит на 10808 пустышку, которая
  сама уходит сразу после проверки. Если отключение всё же случится, следующий
  `vpn …` перезапустит INCY.
- `happ://` ссылки не поддерживаются по той же причине, по которой не
  расшифровываются `incy://`.
- На время импорта (несколько секунд) ссылка — аргумент запуска INCY и видна
  в списке процессов. На общих серверах с чужими пользователями учитывайте это.

Настройки через переменные окружения: `VPN_INCY_PORT` (порт, 10808),
`VPN_INCY_SANDBOX` (`auto`/`on`/`off`), `VPN_INCY_HWID` (закрепить HWID),
`VPN_INCY_VERSION`, `VPN_INCY_DIR`, `VPN_INCY_ASSET`,
`VPN_INCY_TIMEOUT` (секунд на подключение, 60), `VPN_INCY_VNC_PORT` (5917).

### Outline / Shadowsocks (ss://)

Поддерживаются ключи Outline и обычный Shadowsocks, включая Outline-специфичный
параметр `prefix` (маскировка хендшейка под TLS для обхода DPI). Префикс не умеют
ни xray, ни sing-box, поэтому для `ss://` используется собственный хелпер
`outline-proxy` на базе [outline-sdk](https://github.com/Jigsaw-Code/outline-sdk).

В репозитории есть готовые бинарники `outline-proxy` под Linux (amd64) и
macOS (arm64/amd64) — `install.sh` выбирает нужный по `uname`, Go не требуется.
Для других платформ хелпер собирается из исходников (нужен [Go](https://go.dev/dl/)).

**Формат ss:// URL (SIP002 / Outline):**
```
ss://BASE64(method:password)@HOST:PORT?outline=1&prefix=...#имя
```

**Пример:**
```
ss://Y2hhY2hhMjAtaWV0Zi1wb2x5MTMwNTpQQVNTV09SRA@example.com:993/?outline=1&prefix=%17%03%03%3F#My Server
```

При использовании Outline, скрипт автоматически:
1. Чистит URL (отрезает имя, убирает `outline=1`, сохраняет `prefix`)
2. Запускает `outline-proxy` в фоне (если ещё не запущен)
3. Использует локальный HTTP прокси от outline-proxy (127.0.0.1:18082)

Подробности — в [OUTLINE_GUIDE.md](OUTLINE_GUIDE.md).

## Использование

### Базовое использование

Просто добавьте `vpn` перед любой командой:

```bash
# Проверить IP через прокси
vpn curl ifconfig.me

# Скачать файл
vpn wget https://example.com/file.zip

# Клонировать git репозиторий
vpn git clone https://github.com/user/repo.git

# Установить npm пакеты
vpn npm install

# Обновить apt пакеты
vpn apt update
```

### Примеры использования

```bash
# Проверка что прокси работает
curl ifconfig.me           # Покажет ваш реальный IP
vpn curl ifconfig.me       # Покажет IP прокси-сервера

# Скачивание через прокси
vpn wget https://releases.ubuntu.com/22.04/ubuntu-22.04.3-desktop-amd64.iso

# Работа с Docker через прокси
vpn docker pull nginx

# Python pip через прокси
vpn pip install requests

# Браузерные команды через прокси
vpn lynx https://google.com
```

## Обновление прокси

Для смены прокси просто отредактируйте файл `~/.vpn_proxy`:

```bash
nano ~/.vpn_proxy
```

Изменения применятся немедленно при следующем запуске команды с `vpn`.

## Поддерживаемые программы

Работает со всеми программами, которые используют стандартные переменные окружения:
- `http_proxy`
- `https_proxy`
- `HTTP_PROXY`
- `HTTPS_PROXY`

### Протестированные программы:
- ✅ curl
- ✅ wget
- ✅ git
- ✅ apt / apt-get
- ✅ npm / yarn
- ✅ pip
- ✅ docker
- ✅ lynx / w3m
- ✅ python requests
- ✅ go get
- ✅ composer

### Могут не работать:
- ❌ ssh (используйте ProxyCommand в ~/.ssh/config)
- ❌ Некоторые GUI приложения (нужна настройка в самом приложении)
- ❌ Программы использующие только SOCKS прокси

## Удаление

```bash
sudo ./uninstall.sh
```

Или вручную:

```bash
vpn stop all
sudo rm /usr/local/bin/vpn /usr/local/bin/vless_*.sh /usr/local/bin/subscription.sh
rm -rf ~/.vpn_proxy ~/.vpn_country ~/.cache/vpn
```

## Безопасность

**Важно:** Файл `~/.vpn_proxy` содержит ваш логин и пароль в открытом виде!

Рекомендации:
- Установите права `600` на файл (только владелец может читать)
- Не добавляйте файл в git репозиторий
- Используйте отдельный пароль для прокси

```bash
chmod 600 ~/.vpn_proxy
```

```
~/.vpn_proxy                    # конфигурация (подписка / VLESS / ss:// / HTTP-прокси)
~/.vpn_country                  # выбранная страна
~/.cache/vpn/servers.tsv        # кэш списка серверов из подписки
~/.cache/vpn/<страна>/          # конфиг, PID и лог xray для этой страны
~/.local/share/vpn/incy/        # клиент INCY (app/) и его данные (home/)
~/.cache/vpn/incy-box/          # PID, логи, Xvfb коробки INCY
```

## Как это работает

### HTTP Proxy режим

Скрипт `vpn`:
1. Читает данные прокси из `~/.vpn_proxy`
2. Парсит формат `IP:PORT:USER:PASS`
3. Устанавливает переменные окружения:
   - `http_proxy=http://USER:PASS@IP:PORT`
   - `https_proxy=http://USER:PASS@IP:PORT`
   - `HTTP_PROXY=...`
   - `HTTPS_PROXY=...`
4. Запускает вашу команду с этими переменными

### VLESS режим

Когда в `~/.vpn_proxy` указан VLESS URL:
1. Скрипт определяет что это VLESS по префиксу `vless://`
2. Вызывает `vless_parser.sh` для парсинга URL
3. Вызывает `vless_to_xray.sh` для генерации конфигурации xray
4. Запускает xray в фоне (если еще не запущен)
5. Xray создает локальный SOCKS и HTTP прокси на 127.0.0.1
6. Скрипт устанавливает переменные окружения на локальный HTTP прокси
7. Запускает вашу команду через локальный прокси

### Outline режим

Когда в `~/.vpn_proxy` указан ss:// URL:
1. Скрипт определяет что это Outline/Shadowsocks по префиксу `ss://`
2. Вызывает `ss_parser.sh` для очистки URL (имя, `outline=1`, `prefix`)
3. Вызывает `ss_to_outline.sh` для запуска хелпера `outline-proxy`
4. `outline-proxy` поднимает локальный HTTP прокси (порт 18082) и дайлит
   Shadowsocks-соединение с сохранением Outline-префикса
5. Скрипт устанавливает переменные окружения на локальный HTTP прокси
6. Запускает вашу команду через локальный прокси

### Режим подписки

Когда в `~/.vpn_proxy` указан `https://` URL:
1. Скрипт скачивает подписку и декодирует тело: v2ray-JSON, base64 или plain text
2. Для каждой `vless://` ссылки определяет слаг страны — из кода в скобках
   в названии (`🇳🇱 Нидерланды (NL)` → `nl`) или из имени хоста
3. Складывает результат в `~/.cache/vpn/servers.tsv` и обновляет раз в сутки
   (`VPN_SUB_TTL` меняет интервал). Если сеть недоступна — работает на кэше
4. Находит нужную страну: `-c`, затем `~/.vpn_country`, затем первый сервер
5. Поднимает для неё xray на свободной паре портов и запоминает их
   в `~/.cache/vpn/<страна>/ports`
6. Запускает вашу команду через этот локальный прокси

Если сервер для страны в подписке сменился, xray для неё автоматически
перезапускается на новом адресе.

## Управление xray

```bash
# Что сейчас запущено и на каких портах
vpn status

# Остановить одну страну или все сразу
vpn stop de
vpn stop all
```

Для одиночного VLESS также доступно управление напрямую:

```bash
vless_to_xray.sh status
vless_to_xray.sh stop
vless_to_xray.sh restart "vless://..."
```

## Управление outline-proxy (для Outline)

При использовании Outline вы можете управлять хелпером напрямую:

```bash
# Проверить статус
ss_to_outline.sh status

# Остановить
ss_to_outline.sh stop

# Перезапустить с новым ключом
ss_to_outline.sh restart "ss://..."
```

## Troubleshooting

### Команда не работает через прокси

Проверьте что программа поддерживает HTTP_PROXY переменные:

```bash
# Для curl - должно работать
vpn curl -v ifconfig.me

# Проверка переменных
vpn env | grep -i proxy
```

### HTTP прокси недоступен

```bash
# Проверьте доступность прокси
nc -zv PROXY_IP PROXY_PORT

# Или через telnet
telnet PROXY_IP PROXY_PORT
```

### VLESS не работает

```bash
# Проверьте установлен ли xray
which xray

# Проверьте статус
vpn status

# Логи и конфиг для конкретной страны
cat ~/.cache/vpn/de/xray.log
cat ~/.cache/vpn/de/config.json

# Для одиночного VLESS
cat /tmp/xray_vpn.log
```

### Подписка не загружается

```bash
# Принудительно перечитать
vpn update

# Посмотреть что отдаёт сервер
curl -s "$(head -n1 ~/.vpn_proxy)" | base64 -d | head
```

Если сеть недоступна, `vpn` предупредит и продолжит работать на старом кэше.
Чтобы начать с чистого листа, удалите `~/.cache/vpn/servers.tsv`.

### Страна не находится

```bash
# Посмотреть точные слаги
vpn list
```

Искать можно по коду (`de`), хосту (`germany`), префиксу (`neth`) или части
названия в нижнем регистре (`соц`). Если запрос подходит нескольким серверам,
`vpn` покажет варианты и попросит уточнить.

### Программа с именем как у подкоманды

`list`, `use`, `status`, `stop` и `update` — встроенные подкоманды. Чтобы
запустить программу с таким именем, используйте `--`:

```bash
vpn -- status
```

### Неверный формат файла

Первая непустая строка `~/.vpn_proxy`, не являющаяся комментарием, должна быть
в одном из форматов:

```
https://example.com/sub/vless/UUID     подписка
vless://UUID@HOST:PORT?параметры#имя   одиночный VLESS
IP:PORT:USER:PASS                      HTTP-прокси
```

Без пробелов, без лишних символов.

## Тесты

```bash
./test_vless.sh              # весь набор тестов
./test_vless.sh 'vless://…'  # разобрать одну ссылку и показать результат
./test_incy.sh               # коробка INCY без сети
INCY_E2E=1 ./test_incy.sh    # + сквозной тест с настоящим INCY (~1 мин)
```

Сквозной тест поднимает локально два VLESS-сервера, подписку и тестовый сайт,
отдаёт подписку INCY и проверяет: трафик `vpn curl` идёт через INCY, подписку
забрал именно INCY (с `x-client`/`x-hwid`), `vpn use` переключает сервер, через
25 с соединение живо, заглушки перехватили системные вызовы. На macOS это и
есть проверка коробки — запустите его один раз после установки.
